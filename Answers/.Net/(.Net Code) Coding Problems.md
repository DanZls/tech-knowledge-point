# Top 20 Coding Interview Questions — C# / .NET Edition (Simple → Difficult)

A curated list of the most commonly asked *implementation* coding interview
questions (no riddles or "gotcha" trick questions), solved in **C#** using
idiomatic .NET types (`Dictionary<TKey,TValue>`, `Stack<T>`, `Queue<T>`,
`LinkedList<T>`, etc.).

Each entry includes:

- **The problem**
- **The core concept/pattern** being tested
- **Why it's asked** (what it signals to the interviewer)
- **Commented C# solution**
- **Time / Space complexity**

Work through them in order — the patterns build on each other (hash maps →
two pointers → stacks → linked lists → trees → graphs → DP → design).

---

## 1. Two Sum

**Problem:** Given an array of integers `nums` and a target value, return
the indices of the two numbers that add up to the target.

**Concept:** A `Dictionary<int,int>` lets you trade space for time —
instead of checking every pair (O(n²)), you remember what you've already
seen and look it up in O(1).

```csharp
public int[] TwoSum(int[] nums, int target)
{
    // Maps: value -> index of that value, for numbers we've already visited
    var seen = new Dictionary<int, int>();

    for (int i = 0; i < nums.Length; i++)
    {
        int complement = target - nums[i];

        // If we've already seen the number that completes the pair, we're done
        if (seen.TryGetValue(complement, out int matchIndex))
        {
            return new[] { matchIndex, i };
        }

        // Otherwise, remember this number's index for future lookups
        seen[nums[i]] = i;
    }

    return Array.Empty<int>(); // No solution found
}
```

**Complexity:** O(n) time, O(n) space.
**Why asked:** Tests whether you reach for a hash map instead of brute
force — the most fundamental time/space trade-off in interviews.

## 2. Valid Parentheses

**Problem:** Given a string containing `()[]{}`, determine if the brackets
are balanced and properly nested.

**Concept:** A `Stack<char>` naturally models "last opened, first closed."

```csharp
public bool IsValid(string s)
{
    // Maps each closing bracket to its matching opening bracket
    var pairs = new Dictionary<char, char>
    {
        [')'] = '(',
        [']'] = '[',
        ['}'] = '{'
    };

    var stack = new Stack<char>();

    foreach (char c in s)
    {
        if (pairs.ContainsKey(c))
        {
            // It's a closing bracket: the top of the stack must match it
            if (stack.Count == 0 || stack.Pop() != pairs[c])
            {
                return false;
            }
        }
        else
        {
            // It's an opening bracket: push it for later matching
            stack.Push(c);
        }
    }

    // Valid only if every opening bracket found its match
    return stack.Count == 0;
}
```

**Complexity:** O(n) time, O(n) space.
**Why asked:** Introduces the stack pattern, which reappears in expression
parsing, undo systems, and DFS.

## 3. Reverse a Linked List

**Problem:** Reverse a singly linked list in place.

**Concept:** Pointer (reference) manipulation — you must carefully rewire
`Next` references without losing track of the rest of the list.

```csharp
public class ListNode
{
    public int Val;
    public ListNode Next;
    public ListNode(int val = 0, ListNode next = null)
    {
        Val = val;
        Next = next;
    }
}

public ListNode ReverseList(ListNode head)
{
    ListNode prev = null;   // Will become the new head at the end
    ListNode current = head;

    while (current != null)
    {
        ListNode nextNode = current.Next; // Save the next node before overwriting
        current.Next = prev;              // Reverse the pointer
        prev = current;                    // Move prev forward
        current = nextNode;                // Move current forward
    }

    return prev; // prev is now the head of the reversed list
}
```

**Complexity:** O(n) time, O(1) space.
**Why asked:** The classic first test of whether you can reason about
references without drawing a diagram (though you should draw one anyway).

## 4. Valid Palindrome

**Problem:** Determine if a string is a palindrome, considering only
alphanumeric characters and ignoring case.

**Concept:** **Two pointers** moving toward each other from both ends avoid
building a reversed copy of the string.

```csharp
public bool IsPalindrome(string s)
{
    int left = 0, right = s.Length - 1;

    while (left < right)
    {
        // Skip non-alphanumeric characters from the left
        while (left < right && !char.IsLetterOrDigit(s[left]))
        {
            left++;
        }
        // Skip non-alphanumeric characters from the right
        while (left < right && !char.IsLetterOrDigit(s[right]))
        {
            right--;
        }

        // Compare the characters (case-insensitive)
        if (char.ToLower(s[left]) != char.ToLower(s[right]))
        {
            return false;
        }

        left++;
        right--;
    }

    return true;
}
```

**Complexity:** O(n) time, O(1) extra space.
**Why asked:** Tests the two-pointer pattern, which is far more efficient
than reversing and comparing strings.

## 5. Merge Two Sorted Lists

**Problem:** Merge two sorted linked lists into one sorted linked list.

**Concept:** A **dummy head node** simplifies edge cases when building a
new list, avoiding special-casing the first insertion.

```csharp
public ListNode MergeTwoLists(ListNode l1, ListNode l2)
{
    var dummy = new ListNode();  // Placeholder node; dummy.Next will be the real head
    ListNode tail = dummy;

    while (l1 != null && l2 != null)
    {
        if (l1.Val <= l2.Val)
        {
            tail.Next = l1;
            l1 = l1.Next;
        }
        else
        {
            tail.Next = l2;
            l2 = l2.Next;
        }
        tail = tail.Next;
    }

    // Attach whichever list still has leftover nodes (already sorted)
    tail.Next = l1 ?? l2;

    return dummy.Next;
}
```

**Complexity:** O(n + m) time, O(1) extra space (excluding output).
**Why asked:** Builds on linked-list fundamentals and introduces the
dummy-node trick used constantly in list problems.

## 6. Best Time to Buy and Sell Stock

**Problem:** Given an array of daily stock prices, find the maximum profit
from a single buy followed by a single sell.

**Concept:** A single forward pass tracking the **minimum price seen so
far** avoids the O(n²) brute-force pair check.

```csharp
public int MaxProfit(int[] prices)
{
    int minPrice = int.MaxValue; // Lowest price seen so far
    int maxProfit = 0;            // Best profit found so far

    foreach (int price in prices)
    {
        if (price < minPrice)
        {
            minPrice = price; // Found a new best buying point
        }
        else
        {
            int profit = price - minPrice;
            maxProfit = Math.Max(maxProfit, profit); // Track the best sell
        }
    }

    return maxProfit;
}
```

**Complexity:** O(n) time, O(1) space.
**Why asked:** Simple but reveals whether you can spot a greedy,
single-pass solution instead of nested loops.

## 7. Maximum Subarray (Kadane's Algorithm)

**Problem:** Find the contiguous subarray with the largest sum.

**Concept:** **Kadane's Algorithm** — at each position, decide whether to
extend the previous subarray or start fresh, because a negative running sum
can only hurt future sums.

```csharp
public int MaxSubArray(int[] nums)
{
    int currentSum = nums[0]; // Best sum ending exactly at the current index
    int bestSum = nums[0];    // Best sum seen anywhere so far

    for (int i = 1; i < nums.Length; i++)
    {
        // Either extend the previous subarray, or start a new one at nums[i]
        currentSum = Math.Max(nums[i], currentSum + nums[i]);
        bestSum = Math.Max(bestSum, currentSum);
    }

    return bestSum;
}
```

**Complexity:** O(n) time, O(1) space.
**Why asked:** A gateway problem into dynamic programming thinking: define
a state ("best ending here") and a transition rule.

## 8. Binary Search

**Problem:** Given a sorted array, find the index of a target value (or -1
if absent).

**Concept:** Repeatedly halve the search space by comparing against the
middle element — the foundation of all divide-and-conquer thinking.

```csharp
public int BinarySearch(int[] nums, int target)
{
    int left = 0, right = nums.Length - 1;

    while (left <= right)
    {
        int mid = left + (right - left) / 2; // Avoids integer overflow
        if (nums[mid] == target)
        {
            return mid;
        }
        else if (nums[mid] < target)
        {
            left = mid + 1;  // Target must be in the right half
        }
        else
        {
            right = mid - 1; // Target must be in the left half
        }
    }

    return -1; // Target not found
}
```

**Complexity:** O(log n) time, O(1) space.
**Why asked:** Confirms you understand logarithmic time and can implement
the bounds correctly (an easy place to introduce off-by-one bugs). Note:
`Array.BinarySearch` exists in .NET, but interviewers want to see you
implement it yourself.

## 9. Group Anagrams

**Problem:** Given an array of strings, group the anagrams together.

**Concept:** Anagrams share a **canonical form** (their sorted letters), so
that sorted string can serve as a dictionary key.

```csharp
public IList<IList<string>> GroupAnagrams(string[] strs)
{
    // canonical form -> list of matching words
    var groups = new Dictionary<string, List<string>>();

    foreach (string word in strs)
    {
        // Two words are anagrams iff their sorted letters are identical
        char[] chars = word.ToCharArray();
        Array.Sort(chars);
        string key = new string(chars);

        if (!groups.TryGetValue(key, out var list))
        {
            list = new List<string>();
            groups[key] = list;
        }
        list.Add(word);
    }

    return groups.Values.Select(list => (IList<string>)list).ToList();
}
```

**Complexity:** O(n · k log k) time (n words, average length k), O(n · k) space.
**Why asked:** Tests whether you can invent a good hash key for a
non-obvious grouping problem.

## 10. Linked List Cycle Detection

**Problem:** Determine whether a linked list contains a cycle.

**Concept:** **Floyd's Tortoise and Hare** — a slow pointer and a fast
pointer will eventually meet if and only if there's a cycle, because the
fast pointer "laps" the slow one.

```csharp
public bool HasCycle(ListNode head)
{
    ListNode slow = head, fast = head;

    while (fast != null && fast.Next != null)
    {
        slow = slow.Next;        // Moves 1 step at a time
        fast = fast.Next.Next;   // Moves 2 steps at a time

        if (slow == fast)
        {
            return true; // They met -> there's a cycle
        }
    }

    return false; // fast reached the end -> no cycle
}
```

**Complexity:** O(n) time, O(1) space.
**Why asked:** Tests knowledge of a named, elegant algorithm that solves an
O(n) space problem in O(1) space.

## 11. Longest Substring Without Repeating Characters

**Problem:** Find the length of the longest substring without repeating
characters.

**Concept:** **Sliding window** — expand the window by moving the right
edge, and shrink it from the left whenever a duplicate appears.

```csharp
public int LengthOfLongestSubstring(string s)
{
    // character -> most recent index it appeared at
    var lastSeen = new Dictionary<char, int>();
    int windowStart = 0;
    int maxLength = 0;

    for (int windowEnd = 0; windowEnd < s.Length; windowEnd++)
    {
        char c = s[windowEnd];

        // If c is a duplicate INSIDE the current window, shrink from the left
        if (lastSeen.TryGetValue(c, out int lastIndex) && lastIndex >= windowStart)
        {
            windowStart = lastIndex + 1;
        }

        lastSeen[c] = windowEnd;
        // Current window size is windowEnd - windowStart + 1
        maxLength = Math.Max(maxLength, windowEnd - windowStart + 1);
    }

    return maxLength;
}
```

**Complexity:** O(n) time, O(min(n, alphabet size)) space.
**Why asked:** The canonical sliding-window problem — this pattern solves a
huge family of substring/subarray questions.

## 12. Maximum Depth of Binary Tree

**Problem:** Given a binary tree, find its maximum depth (longest path from
root to a leaf).

**Concept:** Simple **recursion**: the depth of a tree is 1 + the deeper of
its two subtrees.

```csharp
public class TreeNode
{
    public int Val;
    public TreeNode Left;
    public TreeNode Right;
    public TreeNode(int val = 0, TreeNode left = null, TreeNode right = null)
    {
        Val = val;
        Left = left;
        Right = right;
    }
}

public int MaxDepth(TreeNode root)
{
    if (root == null)
    {
        return 0; // An empty tree has depth 0
    }

    // Depth = 1 (for this node) + the deeper of the two subtrees
    int leftDepth = MaxDepth(root.Left);
    int rightDepth = MaxDepth(root.Right);
    return 1 + Math.Max(leftDepth, rightDepth);
}
```

**Complexity:** O(n) time, O(h) space for the recursion stack (h = tree height).
**Why asked:** The simplest tree question — confirms comfort with recursive
thinking before harder tree problems.

## 13. Validate Binary Search Tree

**Problem:** Determine if a binary tree is a valid Binary Search Tree (BST).

**Concept:** It's not enough to check each node against its immediate
children — you must pass down a **valid range (low, high)** that narrows
as you descend, since every node in a BST is bounded by its ancestors.

```csharp
public bool IsValidBST(TreeNode root)
{
    return Validate(root, long.MinValue, long.MaxValue);
}

private bool Validate(TreeNode node, long low, long high)
{
    if (node == null)
    {
        return true; // An empty subtree is always valid
    }

    // The node's value must fall strictly within the allowed range
    // (use long to safely handle int.MinValue / int.MaxValue edge cases)
    if (node.Val <= low || node.Val >= high)
    {
        return false;
    }

    // Left subtree: values must stay below node.Val
    // Right subtree: values must stay above node.Val
    return Validate(node.Left, low, node.Val) &&
           Validate(node.Right, node.Val, high);
}
```

**Complexity:** O(n) time, O(h) space.
**Why asked:** A common trap for beginners who only compare parent/child —
this tests whether you think about global tree invariants.

## 14. Binary Tree Level Order Traversal

**Problem:** Return the values of a binary tree grouped by level (top to
bottom).

**Concept:** **BFS with a queue** — process one full level at a time by
tracking how many nodes are currently in the queue.

```csharp
public IList<IList<int>> LevelOrder(TreeNode root)
{
    var result = new List<IList<int>>();
    if (root == null)
    {
        return result;
    }

    var queue = new Queue<TreeNode>();
    queue.Enqueue(root);

    while (queue.Count > 0)
    {
        int levelSize = queue.Count; // Number of nodes at the current level
        var levelValues = new List<int>();

        for (int i = 0; i < levelSize; i++)
        {
            TreeNode node = queue.Dequeue();
            levelValues.Add(node.Val);

            // Enqueue children so they're processed in the next level
            if (node.Left != null) queue.Enqueue(node.Left);
            if (node.Right != null) queue.Enqueue(node.Right);
        }

        result.Add(levelValues);
    }

    return result;
}
```

**Complexity:** O(n) time, O(n) space.
**Why asked:** Tests BFS implementation skills and queue mechanics, a
pattern reused in graph traversal and shortest-path problems.

## 15. Merge Intervals

**Problem:** Given a list of intervals, merge all overlapping intervals.

**Concept:** **Sort first, then sweep** — once intervals are sorted by
start time, any overlap will be with the interval you just processed, so a
single linear pass suffices.

```csharp
public int[][] MergeIntervals(int[][] intervals)
{
    if (intervals.Length == 0)
    {
        return intervals;
    }

    // Sorting by start time means overlaps can only happen with the
    // most recently added interval in the result
    Array.Sort(intervals, (a, b) => a[0].CompareTo(b[0]));

    var merged = new List<int[]> { intervals[0] };

    for (int i = 1; i < intervals.Length; i++)
    {
        int[] last = merged[^1];       // "^1" = last element (index from end)
        int start = intervals[i][0];
        int end = intervals[i][1];

        if (start <= last[1])
        {
            // Overlaps with the last merged interval -> extend it
            last[1] = Math.Max(last[1], end);
        }
        else
        {
            // No overlap -> start a new interval
            merged.Add(intervals[i]);
        }
    }

    return merged.ToArray();
}
```

**Complexity:** O(n log n) time (dominated by the sort), O(n) space.
**Why asked:** Tests whether sorting can simplify an otherwise messy
comparison problem — a very common real-world pattern (calendars, ranges).

## 16. Product of Array Except Self

**Problem:** Given an array `nums`, return an array where each element is
the product of all other elements, **without using division** and in
O(n) time.

**Concept:** Compute **prefix products** and **suffix products**
separately, then combine them — each `result[i]` is (product of everything
before i) × (product of everything after i).

```csharp
public int[] ProductExceptSelf(int[] nums)
{
    int n = nums.Length;
    int[] result = new int[n];

    // Pass 1: result[i] holds the product of all elements BEFORE index i
    int prefix = 1;
    for (int i = 0; i < n; i++)
    {
        result[i] = prefix;
        prefix *= nums[i];
    }

    // Pass 2: multiply in the product of all elements AFTER index i
    int suffix = 1;
    for (int i = n - 1; i >= 0; i--)
    {
        result[i] *= suffix;
        suffix *= nums[i];
    }

    return result;
}
```

**Complexity:** O(n) time, O(1) extra space (excluding the output array).
**Why asked:** Tests creative array manipulation under a tricky constraint
(no division) — a good check on comfort with prefix/suffix techniques.

## 17. Top K Frequent Elements

**Problem:** Given an array of integers, return the `k` most frequent
elements.

**Concept:** **Bucket sort by frequency** avoids a full O(n log n) sort —
since frequency can only range from 1 to n, you can bucket elements by
count and read off the top buckets.

```csharp
public int[] TopKFrequent(int[] nums, int k)
{
    var count = new Dictionary<int, int>();
    foreach (int num in nums)
    {
        count[num] = count.GetValueOrDefault(num, 0) + 1;
    }

    // buckets[i] = list of numbers that appear exactly i times
    var buckets = new List<int>[nums.Length + 1];
    for (int i = 0; i < buckets.Length; i++)
    {
        buckets[i] = new List<int>();
    }

    foreach (var pair in count)
    {
        buckets[pair.Value].Add(pair.Key);
    }

    var result = new List<int>();
    // Walk buckets from highest frequency to lowest
    for (int freq = buckets.Length - 1; freq > 0 && result.Count < k; freq--)
    {
        foreach (int num in buckets[freq])
        {
            result.Add(num);
            if (result.Count == k) break;
        }
    }

    return result.ToArray();
}
```

**Complexity:** O(n) time, O(n) space — better than the O(n log n) you'd get
from sorting by frequency directly.
**Why asked:** Tests whether you know alternatives to "just sort it" when
the data has bounded structure (frequency ≤ n).

## 18. Number of Islands

**Problem:** Given a 2D grid of `'1'` (land) and `'0'` (water), count the
number of islands (connected groups of land, horizontally/vertically
adjacent).

**Concept:** **Graph traversal (DFS/BFS) on a grid** — treat each cell as a
graph node connected to its 4 neighbors, and "sink" every land cell you
visit so it's not counted twice.

```csharp
public int NumIslands(char[][] grid)
{
    if (grid == null || grid.Length == 0)
    {
        return 0;
    }

    int rows = grid.Length;
    int cols = grid[0].Length;
    int count = 0;

    void Sink(int r, int c)
    {
        // Stop if out of bounds or on water — nothing to explore
        if (r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] != '1')
        {
            return;
        }

        grid[r][c] = '0'; // Mark as visited by "sinking" the land

        // Explore all 4 directions
        Sink(r + 1, c);
        Sink(r - 1, c);
        Sink(r, c + 1);
        Sink(r, c - 1);
    }

    for (int r = 0; r < rows; r++)
    {
        for (int c = 0; c < cols; c++)
        {
            if (grid[r][c] == '1')
            {
                count++;     // Found a new island
                Sink(r, c);  // Sink the whole island so it's not recounted
            }
        }
    }

    return count;
}
```

**Complexity:** O(rows × cols) time and space (recursion stack in the
worst case).
**Why asked:** The standard "grid as graph" problem — foundational for
countless graph/matrix questions.

## 19. Coin Change

**Problem:** Given coin denominations and a target amount, find the
**minimum number of coins** needed to make that amount (or -1 if
impossible).

**Concept:** **Bottom-up dynamic programming** — build up the answer for
every amount from 0 to the target, reusing answers to smaller subproblems.

```csharp
public int CoinChange(int[] coins, int amount)
{
    // dp[i] = fewest coins needed to make amount i
    // Initialize with "infinity" (impossible), except dp[0] = 0 coins
    int[] dp = new int[amount + 1];
    Array.Fill(dp, int.MaxValue);
    dp[0] = 0;

    for (int currentAmount = 1; currentAmount <= amount; currentAmount++)
    {
        foreach (int coin in coins)
        {
            if (coin <= currentAmount && dp[currentAmount - coin] != int.MaxValue)
            {
                // Using this coin, the best count is 1 + best count for
                // the remaining amount
                dp[currentAmount] = Math.Min(
                    dp[currentAmount],
                    dp[currentAmount - coin] + 1
                );
            }
        }
    }

    return dp[amount] == int.MaxValue ? -1 : dp[amount];
}
```

**Complexity:** O(amount × number_of_coins) time, O(amount) space.
**Why asked:** A staple "unbounded knapsack" DP problem — tests whether you
can define a DP state and recurrence from scratch.

## 20. LRU Cache (Design Problem)

**Problem:** Design a Least Recently Used (LRU) cache with O(1) `Get` and
`Put` operations.

**Concept:** Combine a **hash map** (`Dictionary<TKey, TValue>`) for O(1)
key lookup with a **doubly linked list** (.NET's `LinkedList<T>` and
`LinkedListNode<T>`) to track usage order — the dictionary points directly
to the linked-list node, so both access and reordering are O(1).

```csharp
public class LRUCache
{
    private readonly int _capacity;
    // Maps key -> the LinkedListNode holding that key/value pair
    private readonly Dictionary<int, LinkedListNode<(int Key, int Value)>> _cache;
    // Order convention: First = most recently used, Last = least recently used
    private readonly LinkedList<(int Key, int Value)> _order;

    public LRUCache(int capacity)
    {
        _capacity = capacity;
        _cache = new Dictionary<int, LinkedListNode<(int Key, int Value)>>();
        _order = new LinkedList<(int Key, int Value)>();
    }

    public int Get(int key)
    {
        if (!_cache.TryGetValue(key, out var node))
        {
            return -1;
        }

        // Accessing counts as "recently used" -> move to the front
        _order.Remove(node);
        _order.AddFirst(node);

        return node.Value.Value;
    }

    public void Put(int key, int value)
    {
        if (_cache.TryGetValue(key, out var existingNode))
        {
            // Key already exists: remove the stale node before reinserting
            _order.Remove(existingNode);
        }

        var newNode = new LinkedListNode<(int Key, int Value)>((key, value));
        _order.AddFirst(newNode);
        _cache[key] = newNode;

        if (_cache.Count > _capacity)
        {
            // Evict the least recently used item, which sits at the end
            var lru = _order.Last;
            _order.RemoveLast();
            _cache.Remove(lru.Value.Key);
        }
    }
}
```

**Complexity:** O(1) time for both `Get` and `Put`, O(capacity) space.
**Why asked:** A favorite "combine two data structures" design question —
tests whether you can reason about a real system (like a caching layer)
rather than just a single algorithm. In .NET, this also checks whether you
know `LinkedList<T>`'s node-based API (`AddFirst`, `Remove(node)`,
`RemoveLast`) instead of reaching for `List<T>` and paying O(n) for
reordering.

## How to use this list

1. **Work top to bottom.** Each problem builds on a pattern used earlier
   (hash maps → two pointers → stacks → linked lists → trees → graphs → DP
   → design).
2. **Say your approach out loud before coding.** Interviewers weight
   reasoning heavily, not just working code.
3. **State time/space complexity unprompted** — it's almost always a
   follow-up question.
4. **Know your .NET collections.** `Dictionary<TKey,TValue>`, `Stack<T>`,
   `Queue<T>`, and `LinkedList<T>` cover almost every pattern here — knowing
   which one gives you O(1) for the operation you need is often the whole
   interview signal.
5. **Re-solve after a few days.** Recognizing the *pattern* (sliding
   window, two pointers, BFS/DFS, DP) matters more than memorizing any
   single solution, since real interview questions are usually variations
   on these.
