## Q5: What is Boxing and Unboxing?

Boxing and unboxing are processes related to converting value types to reference types and vice versa. Boxing occurs when a value type is converted to an object or any interface type it implements, essentially wrapping the value inside an object. It involves copying the value type's data into a heap to reference it. Unboxing reverses the process: it extracts the value type from the object, requiring explicit casting. Both processes can incur performance overhead due to memory allocation and casting operations.

```csharp
int number = 123;
object boxed = number;   // Boxing
int unboxed = (int)boxed; // Unboxing
```

## Q9: What is an unmanaged resource in .NET?

Unmanaged resources are resources that are not managed by the CLR, meaning their memory isn't automatically freed by .NET's garbage collector. Examples include file handles, database connections, and graphic resources. Developers must explicitly release these resources when they're no longer needed, typically by implementing the `IDisposable` interface and defining the disposal pattern within. Proper management of unmanaged resources prevents memory leaks and ensures that resources are released when no longer in use.

```csharp
using System;
using System.IO;

class UnmanagedResourceExample : IDisposable
{
    private FileStream fileStream;

    public UnmanagedResourceExample(string fileName)
    {
        fileStream = new FileStream(fileName, FileMode.Open);
    }

    public void Dispose()
    {
        fileStream?.Dispose();
    }
}
```

## Q13: What is MSIL?

MSIL, or Microsoft Intermediate Language, is the CPU-independent set of instructions that all .NET code compiles into. At runtime, these instructions are converted to native code by the Just-In-Time (JIT) compiler, which allows .NET applications to run on any architecture. MSIL is also known as CIL (Common Intermediate Language) and provides a platform for language interoperability, security measures, and the execution of managed code within the .NET environment.

```csharp

IL_0006: call void [mscorlib]System.Console::WriteLine(string)
```

## Q17: What you understand by Value types and Reference types in .NET? Provide some comparison.

Value types in .NET store their data directly and are generally allocated on the stack, whereas reference types store a reference to their data (object) on the heap. Reference types, including classes and arrays, can be null and therefore require more careful memory management. They allow larger, more complex data structures but have a slight performance overhead due to heap allocation.

## Q22: Explain two types of deployment for .NET Core applications

.NET Core supports Framework-dependent deployment (FDD) and Self-contained deployment (SCD). In FDD, the application relies on a version of .NET Core that is already installed on the target machine, leading to a smaller deployment package but with a dependency on the environment's runtime. This type is useful for environments where .NET Core is pre-installed and centrally managed.

SCD, on the other hand, bundles the .NET Core runtime and libraries with the application, making it independent of the environment's runtime. This results in a larger package but ensures compatibility and consistency, as the application includes all necessary components. SCD is ideal for scenarios where you want to ensure your application runs in environments where .NET Core might not be installed or on specific versions.

```bash
# Example command for each type:
# Framework-dependent deployment
dotnet publish --configuration Release

# Self-contained deployment for Windows
dotnet publish --configuration Release --runtime win-x64 --self-contained
```

## Q24: What is Explicit Compilation?

Explicit Compilation in .NET refers to Ahead-Of-Time (AOT) compilation, where source code is compiled into native code prior to execution, as opposed to Just-In-Time (JIT) compilation where the compilation happens at runtime. Explicit Compilation can lead to improved startup performance, reduced memory usage, and the creation of platform-specific binaries that don't require a JIT runtime.

The process is advantageous for environments with limited resources or for deploying applications where startup speed is critical. It also helps in scenarios where all code paths must be verified prior to deployment, enhancing security by reducing runtime code generation.

```csharp
// Example: Using Publish with AOT Compilation in .NET Native
dotnet publish --configuration Release /p:PublishAot=true
```

AOT can enhance security by reducing runtime code generation, thus minimizing exposure to runtime attacks. ## Q29: What is JIT compiler?

## Q38: Is there a way to catch multiple exceptions at once and without code duplication?

In C#, starting from version 6.0, you can catch multiple exceptions using the `when` keyword to provide conditional exception handling while avoiding code duplication. This approach allows you to specify multiple catch blocks for different exception types and apply the same handling logic. Alternatively, you can use a base exception type (such as `Exception`) and then differentiate exceptions within the catch block using `if-else` statements or a switch pattern. Both methods help reduce code duplication while handling diverse exception scenarios in a unified way.

```csharp
try
{
    // Code that may throw an exception
}
catch (FileNotFoundException ex) when (ex.FileName == "config.json")
{
    Console.WriteLine("Configuration file is missing.");
}
catch (IOException ex)
{
    Console.WriteLine("An I/O error occurred.");
}
// Or using a more generic approach
catch (Exception ex)
{
    switch (ex)
    {
        case FileNotFoundException _:
            Console.WriteLine("File not found.");
            break;
        case IOException _:
            Console.WriteLine("I/O error.");
            break;
    }
}
```
